# 存档规则

本文定义存档基础协议，供不同语言实现参考。当前仅 TypeScript 提供存档管理器、背包快照编解码器和内存存储，C++ 尚未实现对应能力。

## 职责

- 核心管理存档槽、协议校验、编解码调用、操作结果和异步操作顺序。
- 编解码器负责将某种业务数据转换为字符串，以及从字符串恢复经过校验的数据。
- 存储后端负责按字符串键读取、写入和删除字符串。
- 引擎或平台适配层负责实际持久化，不作为核心模块的依赖。

## 槽位与命名空间

槽位 ID 为非空字符串，区分大小写，不自动去除空白。不同命名空间、编解码器 ID 和槽位 ID 相互隔离。

存储键使用紧凑 JSON 数组的序列化结果，顺序为命名空间、编解码器 ID、槽位 ID。例如：

```json
["game-foundation","inventory","slot-1"]
```

存储后端应将该键视为不透明字符串。槽位不是文件路径；文件后端需要自行实现键到安全文件位置的映射。

## 存档外层协议

```json
{
  "format": "game-foundation/save",
  "version": 1,
  "codec": "inventory",
  "data": "编解码器生成的字符串"
}
```

外层协议版本与业务数据版本分开管理。当前只支持外层版本 `1`；业务数据的版本和校验由编解码器负责。

读取时先验证格式标识与外层版本；不支持的版本直接返回版本错误，不按旧结构解释其内容。支持的版本再验证编解码器 ID 和数据类型。非法 JSON、缺少必要字段或数据类型不正确时拒绝加载。当前未提供自动迁移器。

## 保存、读取与删除

- 保存时先编码并捕获当前状态，再调用存储后端。调用后业务对象发生变化，不改变这次保存的内容。
- 编码失败时不触发存储写入，已有存档不变。
- 读取缺失槽位时返回未找到；格式、编解码或数据校验失败时不返回半成品业务对象。
- 删除为幂等操作，后端删除不存在的键应正常完成。
- 存储异常作为业务结果报告，可保留原始异常供调用方处理。

写入完成后的持久性、写入失败时的旧数据保护，以及跨进程一致性，由实际存储后端保证。核心不将普通键值写入等同于持久化事务。

## 异步顺序

同一个管理器内，对同一个槽位的保存、读取和删除按调用顺序执行。较早的慢写入不会在较新的写入之后完成并覆盖它，失败操作不会阻塞后续操作。不同槽位可以独立执行。

此顺序保证限定于同一管理器实例，多个管理器或多个进程共享后端时，需要由后端提供额外协调。

## 背包快照

背包业务数据使用独立的版本化快照：

```json
{
  "version": 1,
  "slotCapacity": 2,
  "stacks": [
    { "item": { "id": "potion", "maxStackSize": 10 }, "quantity": 4 }
  ]
}
```

恢复前检查版本、容量、堆叠数量、物品 ID、堆叠上限、数量和整数范围。同 ID 的堆叠上限必须一致，总数量不得超过实现支持的范围。

合法快照保留堆叠顺序与数量，允许存在多个未满堆叠。恢复创建新背包，复制快照数据，不保留输入对象引用，也不修改已经存在的背包。

## 基础验收

- 保存、读取、覆盖和删除多个独立槽位。
- 相同后端中的数据可由新的管理器实例读取。
- 损坏数据、未知版本、编解码器不匹配和存储异常均可识别。
- 同槽位连续操作遵循调用顺序，不同槽位互不阻塞。
- 编码或读取失败时，已存在的业务对象不被部分修改。
- 内存后端随实例或进程结束而丢失数据，不作为持久化实现。

TypeScript API 与示例见[存档说明](../typescript/docs/save.md)。
