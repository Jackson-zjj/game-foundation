# 背包规则

本文定义各语言版本共同遵循的模块行为。语言相关类型、构建方式和 API 用法分别由对应实现的文档说明。

当前 C++ 和 TypeScript 均已实现基础背包规则并提供独立测试。语言相关的数值范围与查询结果生命周期分别由各版本文档说明。

TypeScript 额外提供版本化快照与存档编解码，格式见[存档规则](save.md)。C++ 尚未提供该能力。

## 基本数据

- 背包容量以格数计算，为非负整数。容量为 `0` 的空背包合法。
- 物品 ID 为非空字符串，区分大小写；物品配置由使用方管理。
- 每种物品具有每格堆叠上限，为正整数，默认值为 `1`。
- 添加或移除请求的数量必须为正整数。
- 每个已使用格子只保存一种物品，数量不超过该物品的堆叠上限。

## 添加

1. 校验物品 ID、堆叠上限和请求数量。
2. 同 ID 物品仍存在于背包时，传入的堆叠上限必须与已有定义一致。
3. 先填充已有的同 ID 堆叠，再使用空闲格子。
4. 即使没有空闲格子，只要已有堆叠能够容纳全部请求，添加仍然成功。
5. 无法容纳全部数量时，整个请求失败，原有物品、数量和已用格数保持不变。

不同 ID 的物品不共享堆叠。某 ID 的物品全部移除后，背包不保留其旧定义，后续可以使用新的堆叠上限添加。

## 移除

1. 校验物品 ID 和请求数量。
2. 持有数量不足或 ID 不存在时，整个请求失败，背包保持原状。
3. 从最后一叠该物品开始消耗，移除空堆叠，尽量释放格子。
4. 剩余堆叠保持相对顺序，空格子不作为独立记录保留。

该版本不承诺稳定的格子索引。业务代码应在修改后重新查询堆叠，不应长期依赖之前的元素位置。

## 查询与失败处理

- 可查询容量上限、已用格数、指定物品总数量和只读堆叠列表。
- 不存在的物品总数量为 `0`。
- 操作结果应区分成功、无效 ID、无效数量、无效堆叠上限、定义冲突、容量不足和持有数量不足。
- 业务校验失败时不执行部分添加或部分移除。
- 具体错误类型和接口命名可以遵循各语言习惯，但含义需要一致。

## 共同验收场景

| 场景 | 预期行为 |
| --- | --- |
| 创建空背包 | 已用格数和各物品数量均为零 |
| 两格背包添加 15 个物品，每格上限 10 | 成功，堆叠数量为 10 和 5 |
| 一格背包已有 4 个物品，上限 10，再添加 6 个 | 成功，仍占用一格 |
| 一格背包已有 8 个物品，上限 10，再添加 3 个 | 容量不足，仍保留 8 个 |
| 背包容量为零，添加一个物品 | 容量不足，背包保持为空 |
| 不同物品 ID 使用相同堆叠上限 | 分别占用格子，不合并 |
| 堆叠上限为 1 | 每个物品单独占用一格 |
| 已有 25 个物品，堆叠为 10、10、5，移除 12 个 | 成功，剩余堆叠为 10 和 3 |
| 持有 15 个物品，移除 16 个 | 数量不足，原有堆叠保持不变 |
| 移除全部物品后再次添加其他物品 | 已释放格子可以复用 |
| 数量为零或负数，ID 为空，或堆叠上限无效 | 拒绝请求，背包保持原状 |
| 同 ID 仍存在时传入不同堆叠上限 | 定义冲突，已有数据保持不变 |

两版实现还应覆盖连续增删后的数量与容量一致性。引用有效期、内存行为等语言特有场景由各版本分别测试。

## 数值范围

通用规则使用整数描述数量，具体边界由各语言实现明确记录。当前 C++ 的容量、请求数量和总数量类型见 [C++ 背包说明](../cpp/docs/inventory.md)。

TypeScript 使用安全整数，单次数量和堆叠上限不得超过 `Number.MAX_SAFE_INTEGER`，添加后同一物品总数量将超出此范围时，返回额外的 `QuantityOverflow` 结果。构造容量使用与 C++ 相同的无符号 32 位范围，具体见 [TypeScript 背包说明](../typescript/docs/inventory.md)。

不能直接假定 JavaScript 的 `number` 可以精确表达 C++ 的所有 64 位整数；涉及共享数据或测试数据时，应明确双方支持的范围。
